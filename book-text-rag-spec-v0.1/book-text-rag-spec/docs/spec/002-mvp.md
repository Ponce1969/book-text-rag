# 002 — Alcance y fases del MVP

Estado: propuesta v0.1. Ejecutar una fase por vez y revisar resultados antes de avanzar.

## Fase 0 — Cierre de decisiones

**No requiere implementación funcional.**

Entregables:
- revisar este spec y listar contradicciones/ambigüedades;
- seleccionar un libro piloto y confirmar formato/fuente;
- comparar opciones de persistencia/indexación con requisitos y coste operativo;
- seleccionar proveedor/modelo de embeddings solo si la búsqueda vectorial se aprueba para el piloto;
- fijar cómo se obtiene el texto y qué metadatos/páginas son fiables;
- acordar criterios de aceptación de la Fase 1.

No instalar ni desplegar servicios durante esta fase. El agente debe presentar opciones con ventajas, límites y recomendación breve; el propietario aprueba las decisiones que condicionan arquitectura.

## Fase 1 — MVP textual de un libro

Incluye:
1. ingesta reproducible de una fuente piloto;
2. extracción de texto y metadatos disponibles;
3. fragmentación jerárquica configurable que respete secciones y párrafos siempre que sea posible;
4. persistencia del documento, fragmentos y versión/configuración de ingesta;
5. recuperación léxica funcional como línea base;
6. resultados con evidencia y procedencia;
7. CLI para ingesta, estado y búsqueda;
8. pruebas automatizadas y documentación de ejecución.

La búsqueda vectorial/híbrida se añade en la fase aprobada siguiente si la decisión de almacenamiento y proveedor queda cerrada. No bloquear la línea base BM25 por la selección de embeddings.

Criterios de aceptación:
- ejecutar dos veces la ingesta de la misma versión no crea duplicados;
- un cambio en la fuente/configuración se detecta y se gestiona explícitamente;
- todo resultado tiene identidad y contenido trazables al documento;
- no se inventan páginas o metadatos ausentes;
- errores de extracción/indexación son visibles y no se presentan como éxito;
- tests y controles estáticos acordados pasan;
- la CLI documenta sus operaciones y no destruye datos por defecto.

## Fase 2 — Evaluación de recuperación

- construir 30–50 preguntas de evaluación para el libro piloto;
- clasificar preguntas léxicas, conceptuales y mixtas;
- anotar pasajes relevantes con revisión humana;
- comparar BM25 con vectorial e híbrida si están implementadas;
- medir Recall@k, MRR y Precision@k cuando las etiquetas lo permitan; registrar latencia y tamaño del índice;
- guardar resultados por versión de índice/configuración para detectar regresiones.

No añadir un LLM juez como dependencia obligatoria. Puede utilizarse después como apoyo, con revisión humana.

## Fase 3 — API HTTP y MCP

Implementar adaptadores sobre los mismos casos de uso ya utilizados por la CLI:
- API HTTP versionada;
- MCP de lectura para `search`, `get_document` y `health`;
- pruebas de contrato equivalentes;
- configuración segura de conexión y límites de consulta.

La separación lógica de adaptadores se define desde el inicio, pero no es obligatorio implementar todos los transportes en la Fase 1.

Criterios de aceptación de esta fase:

- el servicio arranca y permanece en ejecución cuando el índice no está disponible; `health` lo reporta como `degraded` y las consultas responden `index_unavailable`, sin ciclo de reinicio (**D-14**);
- un índice válido sin documentos no se reporta como degradado.

## Fase 4 — Incorporación progresiva de libros

- añadir un libro por iteración;
- conservar versiones y trazabilidad;
- ejecutar evaluación de regresión al ampliar el corpus;
- detectar problemas de extracción antes de indexar silenciosamente contenido degradado.

## Fase 5 — Endurecimiento e integración

Solo cuando el uso real lo justifique:
- métricas operativas, concurrencia y límites;
- backup/restauración probados;
- integración explícita con `book-graph-rag`;
- evaluación de interfaz con `agent-memory` futura;
- escalado vertical/horizontal basado en mediciones.

## Fuera de alcance hasta una decisión nueva

Reranking, contextual retrieval, query rewriting, caché semántica, generación de respuestas, enrutamiento automático grafo/texto, despliegue distribuido y administración de escritura vía MCP.
